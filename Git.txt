### Git 操作提示手册（补充版）

**一、 初始设置（首次使用Git时配置）**

1. **设置用户名和邮箱（全局配置，提交时会记录此信息）**
   ```bash
   git config --global user.name "你的用户名"
   git config --global user.email "你的邮箱"
   ```

2. **检查当前配置**
   ```bash
   git config --list
   ```

**二、 创建仓库与克隆**

1. **在当前目录初始化一个新的Git仓库**
   ```bash
   git init
   ```

2. **克隆一个现有的远程仓库到本地**
   ```bash
   git clone <远程仓库URL>
   # 例如： git clone https://github.com/用户名/仓库名.git
   ```

3. **克隆失败/网络问题处理**（如报错 `RPC failed; curl 92`、`early EOF`、`Failed to connect to github.com port 443`）
   ```bash
   # 增大缓冲区，减少中途断流
   git config --global http.postBuffer 524288000

   # 强制使用 HTTP/1.1（有些网络/代理对 HTTP/2 支持不好）
   git config --global http.version HTTP/1.1

   # 只克隆最新快照，减少传输量
   git clone --depth 1 <远程仓库URL>

   # 走代理（先看加速器/代理软件的实际端口，常见 7890/10809 等）
   git config --global http.proxy http://127.0.0.1:7890
   git config --global https.proxy http://127.0.0.1:7890
   # 或 socks5 代理
   git config --global http.proxy socks5://127.0.0.1:7891
   git config --global https.proxy socks5://127.0.0.1:7891
   # 取消代理（如果加速器是全局/TUN 模式，不需要单独设代理）
   git config --global --unset http.proxy
   git config --global --unset https.proxy

   # 如果代理端口连不上，先确认端口是否正确
   netstat -ano | findstr 7891   # Windows 查看端口是否被监听
   ```

**三、 日常基本工作流程（最常用）**

1. **检查仓库状态**（查看哪些文件被修改、暂存等）
   ```bash
   git status
   ```

2. **将文件添加到暂存区**（准备提交）
   ```bash
   git add <文件名>        # 添加特定文件
   git add .              # 添加所有当前目录下的新文件和修改过的文件
   git add -A             # 添加所有变化（包括新建、修改、删除）
   ```

3. **提交更改到本地仓库**（为本次更改创建一个版本记录）
   ```bash
   git commit -m "提交说明信息"
   # 提交说明应简洁明了，例如：git commit -m "修复用户登录bug"
   ```

4. **将本地提交推送到远程仓库**
   ```bash
   # 已经有仓库，先添加远程仓库
   git remote add origin https://github.com/用户名/仓库名.git

   git push origin <分支名>
   # 例如： git push origin main
   # 首次推送可使用 -u 选项设置上游分支： git push -u origin main
   ```

5. **从远程仓库拉取最新更改到本地**
   ```bash
   git pull origin <分支名>
   # 相当于 git fetch（获取） + git merge（合并）

   # 查看当前远程仓库配置
   git remote -v
   # 如果URL有误，可以重新设置
   git remote set-url origin https://github.com/用户名/仓库名.git
   ```

**四、 分支管理**

1. **查看所有分支**
   ```bash
   git branch              # 查看本地分支（当前分支前有 * 号）
   git branch -a           # 查看所有分支（包括远程分支）
   ```

2. **创建新分支**
   ```bash
   git branch <新分支名>
   ```

3. **切换到指定分支**
   ```bash
   git checkout <分支名>
   ```

4. **创建新分支并立即切换到该分支**（常用）
   ```bash
   git checkout -b <新分支名>
   ```

5. **将指定分支合并到当前分支**
   ```bash
   git merge <要合并过来的分支名>
   ```

6. **删除分支**
   ```bash
   git branch -d <分支名>          # 删除已合并的分支
   git branch -D <分支名>          # 强制删除分支（即使未合并）
   # 删除远程分支
   git push origin --delete <分支名>
   ```

7. **远程分支管理（master 合并到 main / 同步分支）**
   ```bash
   # 本地创建 main 分支并切过去（基于当前 master 内容）
   git checkout -b main
   # 推送到远程，让远程 main 有内容
   git push -u origin main

   # 如果远程 main 是空的或与本地无共同历史，推送被拒时用强制推送
   # （前提：远程 main 没有需要保留的内容）
   git push -u origin main --force
   ```

8. **GitHub 默认分支与 Pull Request 问题**
   - 当 GitHub 的 `main` 分支为空（无提交）时，从 `master` 发 Pull Request 到 `main` 只会显示 compare，没有 merge 按钮，因为两个分支没有共同合并基础。
   - **解决**：先把 `main` 推上有内容（见第 7 点），或到 GitHub 网页 `Settings → Branches → Default branch` 把默认分支改成 `master`。

**五、 查看信息与撤销**

1. **查看提交历史**
   ```bash
   git log                 # 查看详细历史
   git log --oneline       # 查看简洁版历史
   git log --oneline --all # 查看所有分支（含远程）的历史
   git reflog              # 查看所有操作记录（含被撤销/覆盖的操作，用于找回）
   ```

2. **查看文件更改的具体内容**
   ```bash
   git diff                # 查看工作区与暂存区的差异
   git diff --staged       # 查看暂存区与最后一次提交的差异
   ```

3. **撤销操作**
   ```bash
   # 从暂存区撤销某个文件的添加（文件修改内容仍保留在工作区）
   git restore --staged <文件名>

   # 丢弃工作区中某个文件的修改（危险操作，不可恢复！）
   git restore <文件名>

   # 撤销上一次提交，并保留更改到工作区，允许你重新提交
   git reset --soft HEAD~1

   # 撤销上一次提交，并丢弃所有更改（危险操作！）
   git reset --hard HEAD~1
   ```

**六、 远程仓库操作**

1. **查看远程仓库信息**
   ```bash
   git remote -v
   # 注意：远程名字拼写要正确！常见错误是把 origin 拼成 orgin（少个 i）
   # 如果拼错了，重命名：
   git remote rename orgin origin
   ```

2. **添加远程仓库地址**
   ```bash
   git remote add origin <远程仓库URL>
   ```

3. **修改远程仓库地址**
   ```bash
   git remote set-url origin <新的远程仓库URL>
   ```

4. **从远程获取分支信息但不自动合并**
   ```bash
   git fetch
   ```

**七、 解决推送冲突的典型流程**

当 `git push` 失败，提示需要先 `git pull`，而 `git pull` 又产生合并冲突时：

1. **拉取远程代码**（本地与远程历史无关联时加 `--allow-unrelated-histories`）
   ```bash
   git pull origin main --allow-unrelated-histories
   ```

2. **手动解决冲突**
   *   编辑文件中标记有 `<<<<<<<`, `=======`, `>>>>>>>` 冲突的地方。
   *   保留想要的代码，删除冲突标记。

3. **重新添加并提交**
   ```bash
   git add .
   git commit -m "解决合并冲突"
   ```

4. **再次推送**
   ```bash
   git push origin main
   ```

**八、 推送被拒的常见情况及解决**

1. **`fatal: 'origin' does not appear to be a git repository`**
   - 原因：远程名字拼写错误（`orgin` 而非 `origin`），或远程未添加。
   - 解决：`git remote -v` 查看，用 `git remote rename orgin origin` 改名，或用 `git remote add origin <URL>` 添加。

2. **`! [rejected] main -> main (fetch first)`**
   - 原因：远程分支有你本地没有的提交。
   - 解决：先 `git pull` 合并；如果远程分支是空的且无需保留，可用 `git push -u origin main --force` 强制覆盖。

3. **`error: src refspec main does not match any`**
   - 原因：本地没有 `main` 分支（可能是 `master`，或还没有任何提交）。
   - 解决：`git branch` 查看实际分支名，改用正确的分支名；若还没有提交，先 `git add -A` + `git commit`。

4. **`failed to push some refs`（远程有内容，本地没有）**
   - 原因：远程仓库有 README 等初始提交，本地没有。
   - 解决：`git pull origin main --allow-unrelated-histories` 合并后再推送。

**九、 使用 `--git-dir` 和 `--work-tree`（仓库与工作目录分离）**

当你想把另一个文件夹的内容提交到某个已有的 `.git` 仓库，而不移动/复制文件时：

```bash
# 语法：--git-dir 指向 .git 文件夹，--work-tree 指向要纳入的文件目录
git --git-dir "D:\路径\仓库\.git" --work-tree "D:\路径\项目文件夹" add -A
git --git-dir "D:\路径\仓库\.git" --work-tree "D:\路径\项目文件夹" commit -m "说明"
git --git-dir "D:\路径\仓库\.git" push -u origin main
```

**注意：**
- 参数之间必须有空格（不要写成 `.git--work-tree=` 这种粘连形式）。
- 路径含中文/空格时用双引号包住。
- 建议固定工作目录，避免以后解析错位置：
  ```bash
  git --git-dir "D:\路径\仓库\.git" config core.worktree "D:\路径\项目文件夹"
  ```

**十、 文件被覆盖/删除后的恢复**

1. **文件在磁盘上被删除，但 Git 里还存着**（`git status` 显示 `deleted: ...`）：
   ```bash
   # 恢复到当前提交的版本（注意指定正确的工作目录）
   git checkout -- <文件路径>
   # 或恢复所有被删除/修改的文件：
   git checkout -- .
   ```

2. **恢复某个历史版本的文件**：
   ```bash
   git checkout <提交号> -- <文件路径>
   ```

3. **查看历史/操作记录定位**：
   ```bash
   git log --oneline --all   # 找文件在哪个提交里
   git reflog                # 看最近所有操作
   ```

4. **重要提醒**：
   - 恢复前先 `git status` 确认工作目录解析是否正确（`git rev-parse --show-toplevel` 查看顶层目录）。
   - 如果 `core.worktree` 未设置，从其他目录运行命令时 git 可能把当前目录当工作区，导致恢复/提交到错误位置。
   - 恢复前不要执行 `add` / `commit` / `reset --hard`，避免冲掉可恢复的数据。

**十一、 其他实用技巧**

1. **提交后网站没更新？** 因为只 `commit` 了（本地），还没 `push`（推送）。`git pull` 是拉取，不会上传本地提交。要上传必须 `git push origin main`。

2. **换行符提示**（`LF will be replaced by CRLF`）：只影响行尾格式，不影响功能，可忽略。

3. **GitHub 双因素认证（2FA）**：push 时不能用账号密码，要用 Personal Access Token（个人访问令牌）代替密码。

***
**提示：**
*   操作前先使用 `git status` 查看状态是一个好习惯。
*   谨慎使用 `--hard`、`-D`、`--force` 等强制选项，可能导致数据丢失。
*   不确定时，可以先在测试分支上尝试操作。
*   遇到 `git push` 失败，先看报错是「网络问题」还是「分支/历史问题」，再对症下药。
